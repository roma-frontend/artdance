# ArtDance — контекст проекта

Маркетплейс танцевальных услуг для Армении: занятия, инструкторы, аренда залов,
онлайн-курсы, магазин экипировки. Три языка (hy/ru/en), локальные платежи в драмах,
четыре роли пользователей.

Стек: Next.js 16 App Router · React 19 · TypeScript 6 · Tailwind 4 · next-intl 4 ·
Prisma 7 + PostgreSQL · Zod 4 · Vitest 3. Хостинг Vercel, медиа Cloudflare R2.

## Прежде чем писать код

1. **Что строить** — `src/design/component-manifest.ts`: путь файла, состояния,
   namespace i18n, image preset, классы прототипа. Компоненты, которых в прототипе
   нет (формы, таблицы, оверлеи, состояния) — `docs/08-component-catalog.md`.
2. **Как это выглядит** — `design/reference/artdance-final.html`. Это утверждённый
   клиентом дизайн, а не набросок. Отклонения обсуждаются, а не решаются молча.
3. **Порядок работ** — `docs/06-implementation-plan.md`.
4. **Объём сверх макета** — `docs/07-feature-backlog.md`: страницы, фичи,
   монетизация и, главное, поля БД, которые нужно завести **до первой миграции**.
5. **Служебный модуль** — сначала `docs/09-helpers-catalog.md`: сигнатура уже
   описана, второй `formatPhone` проекту не нужен.
6. **Правила** — `.kiro/steering/10-hard-rules.md` (в контексте всегда).
7. **Перед сдачей экрана** — чек-лист `docs/10-polish-and-quality.md` §9.

## Команды

```
npm run verify          # токены, переводы, медиа, типы, линтер, тесты — перед каждым коммитом
npm run verify:headers  # CSP, security-заголовки, кеш, CSRF на живой сборке
npm run verify:admin    # запись админки на живой базе: делегаты Prisma, переводы
npm run design:status   # какие компоненты готовы, какие классы макета не покрыты
npm run media:optimize  # пережать ассеты сида тем же конвейером, что и загрузки
npm run perf:budget     # бюджет веса: JS + изображения (после build)
npm run db:seed         # наполнить БД данными из макета
```

## Границы

- Не добавляй зависимость, если задача решается 30 строками. Проект намеренно
  тонкий: `webhook.ts`, `rate-limit.ts`, `turnstile.ts` написаны без SDK.
- Не создавай второй способ делать то, что уже есть (второй CSRF, второй
  форматтер денег, второй слой кеша). Расширяй существующий.
- Не помечай задачу выполненной без `npm run verify`.
