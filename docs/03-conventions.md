# Правила разработки

Главное правило проекта: **в коде нет абсолютных значений и текстов.**
Цвет, размер, цена, срок отмены, путь, надпись — всё живёт в объявленном месте.

Правила ниже не про стиль, а про стоимость изменений. Когда клиент попросит
«поменяйте окно бесплатной отмены с 24 на 12 часов», это должна быть одна строка,
а не поиск по проекту с риском пропустить место.

## 2. Запрещено (проверяется линтером)

| Нельзя | Надо | Почему |
|---|---|---|
| `style={{ color: '#8B1A2B' }}` | `className="text-accent"` | ребрендинг не должен требовать поиска по проекту |
| `<h2>Найдите свой танец</h2>` | `<h2>{t('discover.title')}</h2>` | текст обязан быть на трёх языках |
| `href="/instructors/anna"` | `href={routes.instructor(slug)}` | переименование раздела — одна правка |
| `import Link from 'next/link'` | `import { Link } from '@/i18n/routing'` | иначе теряется префикс локали |
| `process.env.RESEND_API_KEY` | `getServerEnv().RESEND_API_KEY` | битый деплой падает на старте, а не на платеже клиента |
| `if (hoursUntil < 24)` | `if (hoursUntil < booking.freeCancellationHours)` | это условие договора, а не константа |
| `price * 0.15` | `splitCommission(price, 'CLASS_BOOKING')` | ставка фиксируется в момент операции |
| `import { crimson } from '@/design/tokens/primitives'` | семантический токен | компонент не должен знать конкретный цвет |

Исключение: слой `src/config/**`, `src/design/tokens/**`, `src/i18n/**`,
`src/domain/enums.ts` и `scripts/**`. Это единственное место, где литералы легальны —
там они и есть содержимое.

## 2a. Библиотека компонентов: что берём готовым, а что пишем сами

Ручная реализация диалогов, селектов и календарей — это гарантированные проблемы
с доступностью, поэтому поведение берётся готовым, а внешний вид — наш.

| Слой | Откуда | Почему так |
|---|---|---|
| **Поведение**: диалог, sheet, select, combobox, popover, tabs, accordion, календарь, OTP, таблица | shadcn/ui (37 компонентов в `src/components/ui/`) | Ловушка фокуса, `aria-*`, навигация с клавиатуры, порядок закрытия — это месяцы работы и главный источник замечаний аудита. Компоненты копируются в проект, обновляются командой `npx shadcn add --overwrite` |
| **Бренд**: `Button`, `Badge`, `Price`, `RatingStars`, `SpotsLeft`, `Media` | наши | Здесь важны варианты из дизайн-системы (`accent`, `onCinema`), формат AMD и presets изображений — готовый компонент этого не знает |

Как это связано с токенами: shadcn обращается к своим именам ролей
(`bg-background`, `text-muted-foreground`, `border-input`). В `globals.css` есть
**слой соответствия** — эти имена объявлены ссылками на наши семантические
токены. Значения не дублируются, источник истины один.

Одно переименование сделано вручную: у shadcn роль `accent` означает подсветку
наведения, у нас — брендовое действие. В скопированных файлах `bg-accent`
заменён на `bg-interactive-hover`, иначе наведение на пункт меню становилось бы
бургунди.

Правила при добавлении нового компонента shadcn:

1. `npx shadcn@4.19.1 add <name>` — **без** `--overwrite`, иначе он затрёт наш
   `Button` (он приходит как зависимость `alert-dialog`, `calendar`, `pagination`);
2. заменить в новом файле `accent-foreground` → `content-primary`,
   `bg-accent` → `bg-interactive-hover`;
3. проверить, что все роли из файла есть в слое соответствия;
4. если компонент читает CSS-переменные напрямую (как `sonner`), заменить их
   имена на наши токены.

## 2b. Link и Image: используем Next, но не напрямую

| Нельзя | Надо | Почему |
|---|---|---|
| `import Link from 'next/link'` | `import { Link } from '@/i18n/routing'` | Это тот же Next-Link, обёрнутый next-intl. Без обёртки теряется префикс локали: `/instructors/anna` вместо `/hy/instructors/anna` |
| `import Image from 'next/image'` | `<Media preset="classCard" …>` | `Media` — единственное место с `next/image`. Он подставляет `sizes`, `quality`, размеры и blur из preset. Рассинхрон `sizes` с сеткой не видно на ревью, только замером LCP |
| `useRouter`, `redirect` из `next/navigation` | те же из `@/i18n/routing` | Та же причина: теряется локаль |
| `<video>` в разметке | `HeroVideo` / `VideoPlayer` | Нужны постер, подавление автозапуска при reduced-motion и Save-Data, кнопка паузы (WCAG 2.2.2) |

Все четыре правила проверяет линтер: нарушение — ошибка сборки, а не замечание
на ревью. Исключения объявлены в `eslint.config.mjs` списком файлов, а не
комментариями-отключениями по коду.

## 2c. Контент управляется из админки

Требование заказчика: **фото и видео меняются без разработчика.** Отсюда правило,
которое легко нарушить незаметно:

| Нельзя | Надо |
|---|---|
| `<Media src="hero-dancer" alt={t('hero.imageAlt')} …>` | `<Media {...resolveMedia(content.hero.image, locale)} …>` |
| импорт фикстур в секции | `getHomeContent()` из `src/server/content/` |

Имя файла в разметке означает, что замена фото на главной — это правка кода и
деплой. Поэтому медиа приходит пропсом: `MediaRef` (ключ файла + описание на
трёх языках + точка фокуса) и `VideoRef` (источники по форматам + постер).
Описание изображения лежит рядом с файлом, а не в каталоге переводов: оно
относится к конкретному фото и меняется вместе с ним.

**`src/server/content/home.ts` — единственный шов** между «данными из фикстур» и
«данными из базы». Сегодня он собирает контент из демо-фикстур прототипа, потому
что базы ещё нет. Когда она появится, меняется реализация одной функции, а не
десяток компонентов. Там же появятся кеш-теги и запрос к `ContentBlock`.

Тексты интерфейса (заголовки, CTA, подписи) остаются в i18n: они относятся к
продукту, а не к загруженному файлу.

## 2d. Tailwind v4: где утилиты не существуют, а классы молча исчезают

Две ловушки конкретно этой версии Tailwind. Обе не дают ни ошибки, ни
предупреждения — только вёрстку, отличающуюся от макета.

**1. У `duration-*` и `z-*` нет theme-namespace.** Tailwind сам понимает
`--color-*`, `--ease-*`, `--radius-*` — поэтому `ease-brand` работает. Но
`duration-*` и `z-*` принимают только числа (`duration-300`, `z-50`) либо явную
переменную, и `duration-slow`, написанный по аналогии, **не генерировал никакого
CSS**: класс в разметке был, свойства не было. Такие шкалы объявлены утилитами
явно — генератором токенов, из тех же значений (`buildScaleUtilities` в
`scripts/build-tokens.ts`). Пишем `duration-slow` и `z-header`, а не числа.

Длительность обязана писать **и `--tw-duration`, и `transition-duration`**:
утилиты `transition`, `transition-colors`, `transition-[…]` объявляют
`transition-duration: var(--tw-duration, var(--default-transition-duration))` и
перебивают прямое значение обратно на 150ms. Из-за этого переходы на карточках
выглядели резкими при внешне правильном `duration-slow`.

**1a. Имя CSS-переменной проверяется машинно.** `var(--layout-section-y-wide)`
при опечатке не даёт ни ошибки сборки, ни предупреждения — CSS просто
игнорирует объявление. Так у editorial-секции не было вертикальных отступов
(генератор писал `--layout-section-ywide`), а у плиток направлений — затемнения
под текстом (`--scrim-card-bottom` вместо `--scrim-bottom-strong`). Теперь
`npm run css:check` сверяет каждое `var(--…)` в `src/**` с объявлениями в
`tokens.css` и `globals.css` и входит в `verify`.

**2. `cn()` без настройки выбрасывает наши классы типографики.** tailwind-merge
разрешает конфликты по форме имени: `text-card-title` для него выглядит как цвет
текста, поэтому в паре `cn('text-card-title', 'text-content-primary')` первый
класс **молча исчезал** — заголовок терял гарнитуру, кегль и трекинг. Группы
объявлены явно в `src/lib/utils.ts` из сгенерированного списка имён
(`class-names.generated.ts`), поведение зафиксировано тестами
`src/lib/utils.test.ts`. Новый стиль типографики попадает туда сам.

**Следствие для вендорных компонентов.** У всех портальных компонентов shadcn/ui
зашит `z-50`, а шапка сайта живёт на `--z-header` (1000). Без вмешательства
каждый dropdown, select, tooltip и диалог уходил бы под шапку. Слои назначены
одним правилом по `[data-slot=…]` в `globals.css` — вне `@layer`, потому что
нелейерный CSS имеет приоритет над `utilities`. Вендорные файлы не патчим: их
перезаписывает `shadcn add --overwrite`.

**3. `translate`, `scale` и `rotate` — отдельные CSS-свойства, а не `transform`.**
Это, пожалуй, самая дорогая ловушка версии. Утилиты `-translate-y-1.5`,
`scale-105`, `rotate-2` в Tailwind v4 пишут **не** в `transform`, а в
одноимённые современные свойства. Поэтому переход, перечисляющий `transform`,
к ним не относится: значение меняется мгновенно при формально настроенной
плавности. Симптом — «резкий hover при `duration-slow` в разметке», и по нему
невозможно догадаться о причине.

Правила:

1. Переход для наведения объявляется **классом в `globals.css`**, а не утилитами
   у места вызова: `.card-surface` для подъёма карточки, `.media-zoom` для
   приближения фотографии. Оба перечисляют `translate, scale, rotate, transform`
   полностью. Причина не только в ловушке: любая утилита `transition-*`, дописанная
   рядом, вернула бы длительность к дефолтным 150ms (см. пункт 1).
2. Один класс на все карточки. Пока каждая карточка перечисляла свойства сама,
   дефект воспроизвёлся ровно в одной секции — в инструкторах, где список писался
   руками и в нём не было `scale`.
3. Сброс при `prefers-reduced-motion` тоже обнуляет `translate` и `scale`, а не
   `transform`: карточка продолжала подниматься при просьбе убрать движение.
4. Проверяется поведением, а не наличием класса: `e2e/motion.spec.ts` читает
   `transition-property` у **каждого** `.media-zoom` и требует в нём `scale` и
   `filter`, а подъём проверяет по фактическому изменению `translate` на hover.

## 2g. Фоновое видео первого экрана

Петля живёт в репозитории (`public/media/video/`), но не приходит туда руками:
`npm run video:encode` берёт исходник макета (20,6 МБ, 1920×1080), читает бюджет
из `videoProcessing.heroLoop` и кладёт рядом три файла — AV1, VP9 и H.264.
Браузер скачивает **один** из них, поэтому пользователь платит за самый лёгкий
формат, который поддерживает: 591 KB вместо 1075 KB на современном Chrome.

Вес и длительность попадают в `src/design/hero-video.generated.ts` и оттуда — в
`getHomeContent()`. Компонент не выдумывает вес файла и не хранит его копию в
константе: отчёт о бюджете и админка обязаны рассказывать о файле то, что в нём
действительно есть.

`npm run video:check` проверяет, что файлы на месте и в бюджете, и входит в
`verify`. Он не требует `ffmpeg` — это чтение файловой системы, поэтому работает
и в CI. `ffmpeg` нужен только для переэнкода, то есть при смене исходника или
бюджета.

Что здесь нельзя делать:

1. Класть исходник в `public/`. 20 МБ на первом экране — это трафик, потраченный
   до того, как пользователь увидел первое слово.
2. Ставить `autoplay` без `poster`. Первый кадр — LCP-элемент главной, и без
   постера это пустой прямоугольник.
3. Запускать петлю вопреки настройкам: `prefers-reduced-motion`,
   `prefers-reduced-data`, `Save-Data` и медленное соединение оставляют постер, и
   это полноценное состояние экрана, а не деградация.

## 2e. `loading.tsx` — только у динамических сегментов

`loading.tsx` в сегменте оборачивает в Suspense **каждую** страницу под ним. Для
статически прегенерированного маршрута это означает, что в HTML попадает скелет,
а настоящий `<main>` лежит в `<div hidden>` и вставляется на место инлайновым
скриптом. Последствия: без JavaScript страница пустая, а первым кадром всегда
скелет — на странице, у которой нет ни одного запроса в момент запроса.

Правило: загрузочное состояние добавляется тому сегменту, который действительно
ждёт данные (каталог с фильтрами, кабинет, админка), и никогда — корню локали.
Инвариант закреплён проверкой `e2e/static-rendering.spec.ts`: у статического
маршрута ни один предок `<main>` не может быть скрытым контейнером.

Там же проверяется, что вёрстка не зависит от JavaScript: контент, скрытый до
срабатывания наблюдателя (`Reveal`), обязан быть видимым, если наблюдателя нет.

## 2f. Горизонтальное переполнение ломает мобильную навигацию

Не «портит вид», а именно ломает. Мобильный Chrome при переполнении по горизонтали
расширяет layout viewport на величину переполнения: `window.innerWidth` становится
больше `documentElement.clientWidth`, и координаты касаний перестают совпадать с
картинкой. Найдено на практике: декоративный сдвиг `Reveal` на 80px за край экрана
привёл к тому, что нажатие на бургер попадало в иконку корзины — шесть проверок
мобильной шапки падали по таймауту, и по симптомам это выглядело как флаки-тест.

Правила:

1. Эффект, выносящий блок за край, **обрезает себя сам** (`overflow-x: clip` на
   собственной обёртке), а не надеется, что вызывающая секция не забудет.
2. `html` имеет `overflow-x: clip` как страховку — с `clip`, а не `hidden`, иначе
   ломается `position: sticky` внутри.
3. `body` имеет `overflow-wrap: break-word`: армянские слова длинные, и в узком
   контейнере с крупным кеглем одно слово выходит за экран там, где английский
   текст переносится сам.
4. Инвариант закреплён `e2e/layout-integrity.spec.ts`: обход DOM падает, если
   элемент вылез за край и не обрезан ни одним предком, кроме `html`. Проверка
   идёт на трёх ширинах и трёх локалях — армянская версия ломалась там, где
   английская выглядела нормально.

## 3. Как добавить новую строку интерфейса

1. Добавить ключ в `src/i18n/messages/en.ts` — это эталон структуры.
2. TypeScript немедленно покажет ошибку в `ru.ts` и `hy.ts`: ключ отсутствует.
3. Добавить переводы. `npm run i18n:check` проверит, что ICU-плейсхолдеры совпадают
   и что перевод не остался английским.

Ключи описывают смысл, а не содержимое: `cta.bookNow`, а не `cta.redButton`.
Числа и даты не вставляются в строку — только через плейсхолдеры и `formats`:

```ts
t('common.counts.spotsLeft', { count: 8 })   // «осталось 8 мест»
format.number(price, 'price')                // «12 000 ֏»
format.dateTime(startsAt, 'bookingStamp')    // «сб, 7 сент., 18:00»
```

## 4. Как изменить дизайн-токен

1. Правка в `primitives.ts` или `semantic.ts`.
2. `npm run tokens:build` — перегенерирует `src/styles/tokens.css`.
3. Коммит обоих файлов. В CI `npm run tokens:check` упадёт, если CSS забыли пересобрать.

CSS никогда не правится руками: он производный артефакт.

## 5. Работа с деньгами

- Все суммы — целые драмы (`type Money = number`). `money()` бросает исключение на
  нецелом значении: у AMD нет разменной единицы.
- Округление только через функции `money.ts`. Скидка на заказ распределяется
  `distributeProportionally()` — она гарантирует, что сумма частей равна целому.
- Ставки комиссии и НДС **записываются в БД в момент операции**
  (`Booking.lateCancellationRate`, `Order.vatRate`). Изменение конфига не должно
  переписывать историю: спор с клиентом решается по зафиксированным условиям.

## 6. Работа с платежами

- Только через `getPaymentProvider()`. Импорт конкретного адаптера в бизнес-логике —
  ошибка ревью.
- **Redirect клиента не является доказательством оплаты.** Бронь подтверждается
  после `getPayment()` или проверенного webhook, и никогда по возврату браузера.
- Каждый webhook пишется в `WebhookEvent` с уникальным `(provider, eventId)`.
  Повторная доставка от провайдера не должна подтверждать бронь дважды.
- Создание платежа идемпотентно по `Payment.idempotencyKey`; возврат — по
  `Refund.idempotencyKey`.

## 7. Работа с бронированием

- Слот удерживается через `SlotHold` на `booking.holdTtlMinutes`. Уникальный
  индекс `(instructorId, startsAt)` и `(roomId, startsAt)` физически не даёт двум
  клиентам занять одно время — гонку решает БД, а не код приложения.
- Проверка конфликтов учитывает только статусы из `slotBlockingBookingStatuses`.
- Права проверяются на сервере в самой операции. `proxy.ts` только перенаправляет
  неаутентифицированных: cookie можно подделать, серверный RBAC — нет.

## 8. Контроль качества

```bash
npm run verify   # tokens:check → css:check → i18n:check → media:check → video:check
                 # → design:check → typecheck → lint → test
npm run build    # production-сборка, включая проверку типов
npm run e2e      # поведение в браузере на трёх ширинах (нужна свежая сборка)
```

`verify` должен проходить перед каждым коммитом и в CI на каждый PR.

Каждая проверка в цепочке появилась после конкретного дефекта, а не «на всякий
случай»:

| Проверка | Что ловит |
|---|---|
| `tokens:check` | `tokens.css` разошёлся с `src/design/tokens/*.ts` |
| `css:check` | опечатка в имени `var(--…)`: CSS молча игнорирует объявление |
| `i18n:check` | ключ есть в одном языке и отсутствует в другом |
| `media:check` | ассет в коде есть, файла в `public/` нет |
| `video:check` | петли первого экрана нет или она вышла за бюджет |
| `design:check` | класс прототипа не закреплён ни за одним компонентом |
| `test` (`contrast.test.ts`) | цвет текста не проходит порог AA на подложке, где ему разрешено стоять |

## 8a. Заливка и текст — разные роли

Найдено машинным аудитом на готовом лендинге, а не при вёрстке, и это важная
часть истории: цвет «из макета» и цвет, пригодным для текста, — не одно и то же.

Брендовый бургунди `#8B1A2B` на тёмной подложке даёт **1.8:1**. Им были написаны
надзаголовки секций, цены в карточках и метки — в тёмной теме всё это читалось с
трудом. Золотой `#B89A5E` на белой карточке — 2.7:1, янтарный `#C4841D` — 3.2:1,
`content-tertiary` — 3.5:1 при кегле 12px, которым он и набран.

Правило: у каждой цветной роли есть **текстовый вариант**, и он зависит от темы,
даже когда заливка от темы не зависит.

```
accent          → кнопка, полоса, плашка       (один и тот же в обеих темах)
content-accent  → надзаголовок, цена, метка    (crimson.600 / crimson.300)
metal           → звёзды на кинематографичном фоне
content-metal   → рейтинг и подпись на карточке (gold.700 / gold.400)
```

Исключение — кинематографичные плоскости: они одинаковы в обеих темах, и у них
свои роли (`accent-on-cinema`, `metal`, `content-on-cinema`).

Две проверки, а не одна:

1. **`src/design/tokens/contrast.test.ts`** считает контраст ВСЕХ объявленных пар
   по формуле WCAG, включая двойное наложение полупрозрачной плашки на карточку.
   Проверяется палитра — то есть и те пары, которые встретятся на ещё не
   сверстанных экранах.
2. **`e2e/accessibility.spec.ts`** прогоняет по странице движок axe-core (тот же,
   что внутри Lighthouse) на трёх языках и в двух темах, плюс отдельно — с
   открытым мобильным меню. Он ловит то, чего список пар знать не может:
   фактическую подложку под элементом, роли ARIA, порядок заголовков, доступные
   имена ссылок.

   Аудит страницы идёт на ОДНОЙ ширине, и это не экономия ради экономии:
   контраст, роли и порядок заголовков от размера окна не зависят, а прогон на
   трёх ширинах не находил ничего нового и втрое увеличивал время джоба (лимит в
   двадцать минут был превышен). Ширина проверяется там, где она важна:
   раскладка — `layout-integrity.spec.ts`, мобильное меню — своей проверкой.

Первый отвечает на вопрос «можно ли этим красить текст», второй — «а этим ли
покрасили». Ни один не заменяет другой: аудит нашёл 138 нарушений контраста,
которые тест палитры объяснил четырьмя строками в `semantic.ts`.

Ещё одна находка того же прогона: `role="group"` на `<ul>` **заменяет** роль
списка, и вложенные `<li>` остаются без родителя (нарушение 1.3.1). Имя региону
даёт `aria-label` на самом `<ul>` — список с именем объявляется не хуже группы и
вдобавок сообщает число элементов.

`design:check` — это `design:status --strict`. Он сверяет `class="…"` эталона
(`design/reference/artdance-final.html`) с `prototypeClasses` карты компонентов и
падает, если в макете есть блок, за который никто не отвечает. Так теряются
секции: не «забыли сверстать», а «не заметили, что она там была».

Тесты обязательны для: денежных расчётов, правил бронирования, расчёта комиссий и
возвратов, парсинга webhook.

Для интерактивной вёрстки обязателен e2e: ловушка фокуса, закрытие по `Esc`,
возврат фокуса, порядок слоёв и раскладка на границах ширин — свойства собранной
страницы, а не функции. Unit-тест на них ответить не может, а глазами на каждом
изменении их однажды не проверят. Прогон идёт против production-сборки: у
dev-сервера другой CSS-конвейер, поэтому «работает в dev» ничего не значит.
Браузер ставится один раз: `npm run e2e:install`.

Отдельное правило для e2e на анимацию: **синтетическое наведение — это одно
событие `pointermove`**. Если между замером рамки элемента и движением курсора
блок сдвинулся (а секции въезжают в экран переходом `Reveal`), событие приходит
мимо цели, и тест падает без дефекта в коде. У живого курсора события идут
потоком, поэтому дефект существует только в тесте — но делает его случайным.
Перед наведением ждём, пока элемент перестанет двигаться (`waitUntilStill` в
`e2e/catalog-cards.spec.ts`), а не добавляем таймаут.

`src/domain/enums.test.ts` сверяет enum'ы Prisma и TypeScript. Это единственное
допустимое дублирование в проекте, и тест делает его безопасным.
