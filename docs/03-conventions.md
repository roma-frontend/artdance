# Правила разработки

Главное правило проекта: **в коде нет абсолютных значений и текстов.**
Цвет, размер, цена, срок отмены, путь, надпись — всё живёт в объявленном месте.

Правила ниже не про стиль, а про стоимость изменений. Когда клиент попросит
«поменяйте окно бесплатной отмены с 24 на 12 часов», это должна быть одна строка,
а не поиск по проекту с риском пропустить место.

---

## 1. Где что лежит

| Что | Где | Пример |
|---|---|---|
| Цвета, размеры, тайминги, слои | `src/design/tokens/primitives.ts` | `crimson[600] = '#8B1A2B'` |
| Роли цветов и типографики | `src/design/tokens/semantic.ts` | `accent`, `heading-2` |
| Любой текст для пользователя | `src/i18n/messages/{hy,ru,en}.ts` | `home.hero.badge` |
| Переменные окружения | `src/config/env.ts` | `DATABASE_URL` |
| Бренд, контакты, домены, часовой пояс | `src/config/site.ts` | `site.timeZone` |
| Пути и API-роуты | `src/config/routes.ts` | `routes.instructor(slug)` |
| Бизнес-правила и лимиты | `src/config/business.ts` | `booking.freeCancellationHours` |
| Тарифы, планы, комиссии | `src/config/pricing.ts` | `subscriptionPlans.pro` |
| Включение/отключение модулей | `src/config/features.ts` | `features.shop` |
| Presets изображений | `src/config/media.ts` | `imagePresets.instructorCard` |
| Словари домена | `src/domain/enums.ts` | `danceStyles` |
| Денежная арифметика | `src/domain/money.ts` | `splitCommission()` |
| Бизнес-ошибки | `src/domain/errors.ts` | `domainErrors.slotConflict()` |

Импорт конфигурации — всегда через барьер: `import { routes, businessRules } from '@/config'`.

## 2. Запрещено (проверяется линтером)

| Нельзя | Надо | Почему |
|---|---|---|
| `style={{ color: '#8B1A2B' }}` | `className="text-accent"` | ребрендинг не должен требовать поиска по проекту |
| `<h2>Найдите свой танец</h2>` | `<h2>{t('discover.title')}</h2>` | текст обязан быть на трёх языках |
| `href="/instructors/anna"` | `href={routes.instructor(slug)}` | переименование раздела — одна правка |
| `import Link from 'next/link'` | `import { Link } from '@/i18n/routing'` | иначе теряется префикс локали |
| `process.env.RESEND_API_KEY` | `getServerEnv().RESEND_API_KEY` | битый деплой падает на старте, а не на платеже клиента |
| `if (hoursUntil < 24)` | `if (hoursUntil < booking.freeCancellationHours)` | это условие договора, а не константа |
| `price * 0.15` | `splitCommission(price, 'CLASS_BOOKING')` | ставка фиксируется в момент операции |
| `import { crimson } from '@/design/tokens/primitives'` | семантический токен | компонент не должен знать конкретный цвет |

Исключение: слой `src/config/**`, `src/design/tokens/**`, `src/i18n/**`,
`src/domain/enums.ts` и `scripts/**`. Это единственное место, где литералы легальны —
там они и есть содержимое.

## 2a. Библиотека компонентов: что берём готовым, а что пишем сами

Ручная реализация диалогов, селектов и календарей — это гарантированные проблемы
с доступностью, поэтому поведение берётся готовым, а внешний вид — наш.

| Слой | Откуда | Почему так |
|---|---|---|
| **Поведение**: диалог, sheet, select, combobox, popover, tabs, accordion, календарь, OTP, таблица | shadcn/ui (37 компонентов в `src/components/ui/`) | Ловушка фокуса, `aria-*`, навигация с клавиатуры, порядок закрытия — это месяцы работы и главный источник замечаний аудита. Компоненты копируются в проект, обновляются командой `npx shadcn add --overwrite` |
| **Бренд**: `Button`, `Badge`, `Price`, `RatingStars`, `SpotsLeft`, `Media` | наши | Здесь важны варианты из дизайн-системы (`accent`, `onCinema`), формат AMD и presets изображений — готовый компонент этого не знает |

Как это связано с токенами: shadcn обращается к своим именам ролей
(`bg-background`, `text-muted-foreground`, `border-input`). В `globals.css` есть
**слой соответствия** — эти имена объявлены ссылками на наши семантические
токены. Значения не дублируются, источник истины один.

Одно переименование сделано вручную: у shadcn роль `accent` означает подсветку
наведения, у нас — брендовое действие. В скопированных файлах `bg-accent`
заменён на `bg-interactive-hover`, иначе наведение на пункт меню становилось бы
бургунди.

Правила при добавлении нового компонента shadcn:

1. `npx shadcn@4.19.1 add <name>` — **без** `--overwrite`, иначе он затрёт наш
   `Button` (он приходит как зависимость `alert-dialog`, `calendar`, `pagination`);
2. заменить в новом файле `accent-foreground` → `content-primary`,
   `bg-accent` → `bg-interactive-hover`;
3. проверить, что все роли из файла есть в слое соответствия;
4. если компонент читает CSS-переменные напрямую (как `sonner`), заменить их
   имена на наши токены.

## 2b. Link и Image: используем Next, но не напрямую

| Нельзя | Надо | Почему |
|---|---|---|
| `import Link from 'next/link'` | `import { Link } from '@/i18n/routing'` | Это тот же Next-Link, обёрнутый next-intl. Без обёртки теряется префикс локали: `/instructors/anna` вместо `/hy/instructors/anna` |
| `import Image from 'next/image'` | `<Media preset="classCard" …>` | `Media` — единственное место с `next/image`. Он подставляет `sizes`, `quality`, размеры и blur из preset. Рассинхрон `sizes` с сеткой не видно на ревью, только замером LCP |
| `useRouter`, `redirect` из `next/navigation` | те же из `@/i18n/routing` | Та же причина: теряется локаль |
| `<video>` в разметке | `HeroVideo` / `VideoPlayer` | Нужны постер, подавление автозапуска при reduced-motion и Save-Data, кнопка паузы (WCAG 2.2.2) |

Все четыре правила проверяет линтер: нарушение — ошибка сборки, а не замечание
на ревью. Исключения объявлены в `eslint.config.mjs` списком файлов, а не
комментариями-отключениями по коду.

## 3. Как добавить новую строку интерфейса

1. Добавить ключ в `src/i18n/messages/en.ts` — это эталон структуры.
2. TypeScript немедленно покажет ошибку в `ru.ts` и `hy.ts`: ключ отсутствует.
3. Добавить переводы. `npm run i18n:check` проверит, что ICU-плейсхолдеры совпадают
   и что перевод не остался английским.

Ключи описывают смысл, а не содержимое: `cta.bookNow`, а не `cta.redButton`.
Числа и даты не вставляются в строку — только через плейсхолдеры и `formats`:

```ts
t('common.counts.spotsLeft', { count: 8 })   // «осталось 8 мест»
format.number(price, 'price')                // «12 000 ֏»
format.dateTime(startsAt, 'bookingStamp')    // «сб, 7 сент., 18:00»
```

## 4. Как изменить дизайн-токен

1. Правка в `primitives.ts` или `semantic.ts`.
2. `npm run tokens:build` — перегенерирует `src/styles/tokens.css`.
3. Коммит обоих файлов. В CI `npm run tokens:check` упадёт, если CSS забыли пересобрать.

CSS никогда не правится руками: он производный артефакт.

## 5. Работа с деньгами

- Все суммы — целые драмы (`type Money = number`). `money()` бросает исключение на
  нецелом значении: у AMD нет разменной единицы.
- Округление только через функции `money.ts`. Скидка на заказ распределяется
  `distributeProportionally()` — она гарантирует, что сумма частей равна целому.
- Ставки комиссии и НДС **записываются в БД в момент операции**
  (`Booking.lateCancellationRate`, `Order.vatRate`). Изменение конфига не должно
  переписывать историю: спор с клиентом решается по зафиксированным условиям.

## 6. Работа с платежами

- Только через `getPaymentProvider()`. Импорт конкретного адаптера в бизнес-логике —
  ошибка ревью.
- **Redirect клиента не является доказательством оплаты.** Бронь подтверждается
  после `getPayment()` или проверенного webhook, и никогда по возврату браузера.
- Каждый webhook пишется в `WebhookEvent` с уникальным `(provider, eventId)`.
  Повторная доставка от провайдера не должна подтверждать бронь дважды.
- Создание платежа идемпотентно по `Payment.idempotencyKey`; возврат — по
  `Refund.idempotencyKey`.

## 7. Работа с бронированием

- Слот удерживается через `SlotHold` на `booking.holdTtlMinutes`. Уникальный
  индекс `(instructorId, startsAt)` и `(roomId, startsAt)` физически не даёт двум
  клиентам занять одно время — гонку решает БД, а не код приложения.
- Проверка конфликтов учитывает только статусы из `slotBlockingBookingStatuses`.
- Права проверяются на сервере в самой операции. `proxy.ts` только перенаправляет
  неаутентифицированных: cookie можно подделать, серверный RBAC — нет.

## 8. Контроль качества

```bash
npm run verify   # tokens:check → i18n:check → typecheck → lint → test
npm run build    # production-сборка, включая проверку типов
```

`verify` должен проходить перед каждым коммитом и в CI на каждый PR.

Тесты обязательны для: денежных расчётов, правил бронирования, расчёта комиссий и
возвратов, парсинга webhook. Для вёрстки — по необходимости.

`src/domain/enums.test.ts` сверяет enum'ы Prisma и TypeScript. Это единственное
допустимое дублирование в проекте, и тест делает его безопасным.

## 9. Открытые вопросы

Требуют решения до соответствующего этапа.

| Вопрос | Кто решает | Блокирует |
|---|---|---|
| Акцент: бургунди `#8B1A2B` или красный `#D6162B` | заказчик | отрисовку макетов |
| Ставки комиссии: 15% инструктор / 12% площадка | заказчик | Фазу 3 (выплаты) |
| Окно бесплатной отмены: 24 ч; удержание при поздней отмене: 50% | заказчик, юрист | публикацию оферты |
| Плата за выезд инструктора: 5 000 AMD | заказчик | модуль бронирования |
| Порог бесплатной доставки: 25 000 AMD | заказчик | оформление заказа |
| Режим налогообложения и ставка НДС | бухгалтер заказчика | выставление счетов |
| Банк-эквайрер и комиссия | заказчик | production-запуск (не разработку) |
| SMS-провайдер и регистрация имени отправителя | заказчик | production-запуск |
| Вычитка армянских переводов носителем | заказчик | production-запуск |
| Юридические документы: оферта, политика возврата, privacy | юрист заказчика | приём платежей |
| Реквизиты юрлица: ИНН, адрес, телефон в `site.ts` | заказчик | выставление счетов |

Все параметры с пометкой `@confirm` в `src/config/business.ts` — из этого списка.
