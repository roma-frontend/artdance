# Полировка: движение, доступность, скорость

Разница между «свёрстано по макету» и «выглядит дорого» — это движение, состояния
и мелочи, которых в статичном HTML не видно. Здесь они собраны заранее, потому что
после сдачи фазы их уже не добавляют: они размазаны по всем компонентам.

Всё, что ниже, опирается на уже существующие токены: `duration`, `easing`,
`zIndex`, `radius`, `shadow*`, `breakpoint`, `aspectRatio` в
`src/design/tokens/primitives.ts`. Числа в CSS-правилах по месту — нарушение
конвенций.

---

## 1. Движение

### Что берётся из прототипа

| Эффект | Токен | Где |
|---|---|---|
| Медленный зум фона | `duration.kenBurns` (12s) | hero, editorial |
| Бегущая строка | `duration.marquee` (40s) | `StyleMarquee` |
| Счётчики показателей от нуля | `duration.slower` | `HeroSection` |
| Подъём карточки на hover | `duration.normal` + `easing.brand` | все карточки |
| Зум фото внутри карточки | `duration.slow` | `cat`, `cc-img`, `card-img` |
| Смена фона навигации при скролле | `duration.fast` | `SiteHeader` (порог 40px) |

### Что стоит добавить

| Приём | Зачем | Стоимость |
|---|---|---|
| **View Transitions** на переходе карточка → страница сущности | Фото продолжает движение вместо мигания страницы. Самый заметный «дорогой» эффект за минимальные деньги; Next 16 поддерживает нативно | 6 ч |
| Появление секций по `IntersectionObserver` (`Reveal`) | Длинная главная перестаёт быть простыней. Только один раз, без повторов при обратном скролле | 4 ч |
| Скролл-анимации через `animation-timeline` | Параллакс и прогресс без JS, не грузят главный поток | 6 ч |
| Оптимистичные переходы для избранного, корзины, лайков | Действие ощущается мгновенным; откат при ошибке с тостом | 6 ч |
| Морфинг skeleton → контент (crossfade 160ms) | Убирает «щелчок» подмены | 3 ч |
| Пружина на удержании слота в последнюю минуту | Обратный отсчёт должен нервировать — это работающий стимул завершить оплату | 2 ч |

### Правила

- Анимируются только `transform` и `opacity`. `width`, `height`, `top` — нет:
  это layout thrashing, и на среднем Android это видно.
- Всё, что дольше `duration.normal`, обязано быть прерываемым.
- `prefers-reduced-motion: reduce` — глобальное правило в `globals.css`,
  отключающее анимации и оставляющее конечные состояния; для параллакса и
  счётчиков — отдельная проверка в компоненте, потому что там анимация в JS.
- Hover-эффекты дублируются `:focus-visible`. Дефект эталона: `Quick Add` и `♡`
  доступны только по hover — на телефоне их нет вообще.

## 2. Обязательные состояния

Каждый экран — четыре состояния (`docs/05-screen-inventory.md`), каждый
интерактивный элемент — шесть.

| Элемент | Состояния |
|---|---|
| Кнопка | `default`, `hover`, `active`, `focus-visible`, `disabled`, `loading` |
| Поле | `default`, `focus`, `filled`, `invalid`, `disabled`, `readonly` |
| Список | `loading`, `items`, `empty`, `error`, `end-of-list` |
| Карточка | `default`, `hover`, `pressed`, `unavailable`, `skeleton` |
| Действие с сервером | `idle`, `pending`, `success`, `error`, `conflict` |

Про skeleton: он повторяет геометрию финального блока. Skeleton «на глаз» даёт
скачок вёрстки при загрузке, и это ухудшает CLS сильнее, чем его отсутствие.

Про `conflict`: это состояние существует только в бронировании и только там его
забывают. «Слот заняли, пока вы платили» — отдельный экран с альтернативами, а не
красный текст.

## 3. Доступность

Не благотворительность: это условие для корпоративных клиентов и способ не потерять
пользователей с плохим зрением на макете, где половина текста — светло-серый на
светло-бежевом.

| Требование | Как проверяется |
|---|---|
| Контраст текста ≥ 4.5:1, крупного ≥ 3:1 | `npm run tokens:check` расширить проверкой пар. **Известный дефект эталона:** `--text3` на ivory не проходит — использовать `content-secondary` |
| Фокус видим всегда | `border-focus` через `:focus-visible`, обводка 2px + отступ 2px. Обнуление `outline` без замены запрещено |
| Цель нажатия ≥ 44×44px | Ревью на 375px. В макете `nav-icon` и `cc-fav` меньше |
| Клавиатура покрывает всё | Календарь (стрелки, `Home`/`End`, `PageUp`/`PageDown`), карусель (стрелки + кнопки), диалог (ловушка фокуса, `Esc`), палитра команд |
| Скрытый текст для иконок | `a11y.*` в i18n. Звёзды рейтинга обязаны иметь `a11y.ratingStars` — в эталоне их нет |
| Живые области | Корзина, тосты, результаты поиска — `aria-live="polite"`; ошибки — `assertive` |
| Заголовки по порядку | Один `h1` на страницу; секции — `h2`; `SectionHeading` не должен позволять выбрать уровень «для красоты» |
| Ссылка «к содержимому» | Первый focusable элемент в `layout.tsx` |
| `lang` на `<html>` | Из локали. Без него экранный диктор читает армянский с английской фонетикой |
| Формы | `label` связан, ошибка через `aria-describedby`, `aria-invalid`; ошибки не только цветом |
| `forced-colors`, `prefers-reduced-transparency` | Границы вместо теней, отказ от `backdrop-filter` |
| Изображения | Осмысленный `alt` из `MediaAsset.altText`; декоративные — `alt=""`, а не «фото» |

Армянский текст: `Noto Sans Armenian` уже подключён, но у армянских глифов другая
высота строчных. Для `hy` нужны отдельные `line-height` и трекинг заголовков —
иначе крупный display-текст выглядит разреженным. Это правка в семантической
типографике, а не в компонентах.

## 4. Скорость

Бюджет уже автоматизирован (`npm run perf:budget`: 90 KB gzip на начальный чанк,
260 KB всего). Ниже — приёмы, которые удерживают его при росте функциональности.

| Приём | Эффект |
|---|---|
| LCP-элемент на экран определён заранее и только он с `priority` | Два `priority` на странице = оба грузятся медленнее |
| Сид-ассеты пережаты конвейером: 6712 KB → 967 KB (`npm run media:optimize`) | Задача 1.2 закрыта. Hero 1888 KB → 56 KB, editorial 1469 KB → 38 KB |
| `npm run perf:budget` считает и JS, и изображения | «Зелёный бюджет бандла» при мегабайтном hero — самообман |
| Картинка карты вместо JS-карты в листингах | Maps SDK — ~120 KB и блокировка потока; в листинге интерактив не нужен |
| Аналитика, карты, чат — только после согласия на cookie | Сторонние скрипты в начальном бандле дают тот же эффект, что Sentry client SDK: 178 KB gzip, уже поймано и убрано в динамический импорт |
| `<Suspense>` вокруг каждой секции главной | Hero отдаётся сразу, карусели догружаются потоком |
| Курсорная пагинация вместо `offset` | На 10 000 записях `OFFSET 9900` — секунды |
| `Save-Data` и `prefers-reduced-data` | Видео → постер, галерея → одно фото. Мобильный интернет в регионах |
| Шрифты: `subsets` строго по локали, `preload` только для UI-гарнитуры | Армянский набор не должен грузиться на английской версии |
| `revalidateTag` вместо `revalidatePath` | Точечная инвалидация: цена одного занятия не сбрасывает кеш каталога |
| Никаких библиотек дат | `Intl` покрывает форматирование; хелперы времени свои (`docs/09-helpers-catalog.md`) |

Отдельно: **на каждый экран фиксируется LCP-элемент** и записывается в манифест
компонентов заметкой. Без этого через два месяца никто не помнит, почему на
странице занятия `priority` стоит на обложке, а не на аватаре инструктора.

## 5. Мобильные детали

Макет проверен на 375, 768 и 1440. Этого мало — ниже то, что ломается на реальных
устройствах.

| Деталь | Решение |
|---|---|
| Адресная строка меняет высоту | `100dvh` вместо `100vh` в hero, иначе первый экран «дёргается» при скролле |
| Вырезы и домашняя полоса | `env(safe-area-inset-*)` в `StickyActionBar` и `BottomNav` |
| iOS зумит при фокусе на поле | `font-size` полей ≥ 16px |
| Клавиатура закрывает кнопку | `StickyActionBar` учитывает `visualViewport` |
| Действия только по hover | Дублируются видимой кнопкой на `(hover: none)` |
| Горизонтальные карусели | `scroll-snap` + видимая полоса прогресса: иначе не понятно, что там ещё есть контент |
| Фильтры на телефоне | `Sheet` снизу с кнопкой «Показать N», а не сворачивающиеся блоки |
| Панель бронирования | Sticky на десктопе, фиксированная снизу на мобильном: цена и CTA всегда видны |
| Двойной тап и подсветка | `-webkit-tap-highlight-color`, `touch-action: manipulation` |
| Длинные армянские слова | `hyphens` и `overflow-wrap: anywhere` в заголовках карточек |

## 6. Тёмная тема

Тема уже разведена на `lightColors` / `darkColors`, но три вещи требуют внимания
при вёрстке.

1. **`surface-cinema` не зависит от темы.** Hero и editorial остаются тёмными
   всегда. Попытка «осветлить их в светлой теме» ломает брендовый контраст.
2. **Тени в тёмной теме не работают.** Вместо `shadow-md` — `border-subtle`.
   Поднятие плоскости передаётся цветом поверхности, а не тенью.
3. **Фотографии в тёмной теме кажутся ярче.** На карточках нужен лёгкий
   затемняющий слой, иначе сетка выглядит как набор световых пятен.

Плюс: тема пишется в cookie и читается на сервере — переключение не должно
вызывать вспышку светлой темы при загрузке.

## 7. Микрокопия

Тексты живут в i18n, но принципы их написания нигде не зафиксированы — а
несогласованный тон заметен сильнее, чем несогласованные отступы.

| Ситуация | Плохо | Хорошо |
|---|---|---|
| Ошибка | «Произошла ошибка» | «Не удалось забронировать: слот заняли. Вот три ближайших времени» |
| Пустой список | «Ничего не найдено» | «По этим фильтрам занятий нет. Убрать фильтр по цене?» |
| Отмена | «Вы уверены?» | «Отменить бронь на сб, 7 сент.? Вернём 12 000 ֏ на карту в течение 5 дней» |
| Ожидание | «Загрузка…» | «Проверяем доступность» |
| Успех | «Готово» | «Бронь подтверждена. Письмо с деталями отправлено на a\*\*\*@mail.ru» |

Правила: ошибка говорит **что случилось и что делать**; в подтверждениях
необратимых действий называются последствия в деньгах и датах; обращение на «вы»
без заглавной; никаких «упс» и «ой».

Три языка — три длины. Армянский и русский длиннее английского на 20–40%: кнопки
и бейджи проверяются на самом длинном переводе, а не на английском.

## 8. Письма и печать

| Что | Требование |
|---|---|
| Письма | Таблицы, инлайновые стили, ширина 600px, обязательная текстовая версия. Тёмная тема почтовых клиентов ломает прозрачные логотипы — PNG с фоном |
| Шрифты в письмах | Системные. Кастомные не поддерживаются половиной клиентов |
| Ссылки в письмах | С локалью и UTM из реестра `config/analytics.ts` |
| Печать счёта и пропуска | Отдельные стили: без навигации, без тёмного фона, QR не меньше 2 см, `@page` с полями |

## 9. Чек-лист готовности экрана

Дополняет «правило завершения задачи» из плана. Экран не сдан, пока не пройден
весь список.

```
[ ] 4 состояния: загрузка, пусто, ошибка, нет доступа
[ ] Skeleton повторяет геометрию финального блока
[ ] 375 / 768 / 1440 px, светлая и тёмная тема
[ ] Проверен на самом длинном переводе (обычно hy или ru)
[ ] Полная навигация с клавиатуры, фокус видим
[ ] Все интерактивные элементы ≥ 44px, hover продублирован
[ ] Иконки и звёзды имеют текстовую альтернативу
[ ] Один h1, порядок заголовков не нарушен
[ ] LCP-элемент определён, priority только на нём
[ ] generateMetadata: canonical, hreflang, OG-картинка
[ ] JSON-LD по типу сущности, aggregateRating только при достаточном числе отзывов
[ ] prefers-reduced-motion не ломает вёрстку
[ ] Ни одного литерала: цвет, текст, путь, бизнес-константа
```

Первые четыре пункта закрывают около 80% замечаний на приёмке, и все четыре
нельзя увидеть в статичном макете — поэтому список и существует.
