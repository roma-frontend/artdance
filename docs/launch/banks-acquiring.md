# Письма банкам: интернет-эквайринг (шаг 0.6)

Код фазы 5 работает на mock-провайдере и банка не ждёт, но договор с
эквайрером — самый долгий внешний путь проекта (1–3 недели на ответы, потом
подключение). Письма уходят **всем адресатам одновременно**: ответы
сравниваются, выбор делается по комиссии и качеству документации, а не по
очерёдности ответа.

Кого и почему:

| Адресат               | Роль в коде             | Что запрашиваем                        |
| --------------------- | ----------------------- | -------------------------------------- |
| **Arca bank** (EPG)   | провайдер `arca-epg`    | интернет-эквайринг, тестовый доступ    |
| **Ameriabank** (VPOS) | провайдер `ameria-vpos` | интернет-эквайринг, тестовый доступ    |
| **Idram**             | провайдер `idram`       | приём платежей через Idram Wallet      |
| **Paynet**            | провайдер `paynet`      | единый API: карты ARCA, Idram, Telcell |

Оплата — в драмах (AMD), модель площадки: комиссия с инструктора и площадки
(маркетплейс), деньгами платформа не владеет — требуется **split либо
регулярный расчётный период**, это главный вопрос к каждому банку.

---

## Что писать в каждом письме (7 пунктов)

1. Кто вы: ИП/ООО, название, сфера — онлайн-платформа бронирования занятий
   танцами и продаж сопутствующих товаров (маркетплейс).
2. Что нужно: интернет-эквайринг для сайта (3D-Secure обязателен), валюта
   расчётов AMD, оплата картами ARCA/Visa/Mastercard + кошельки.
3. Главный вопрос маркетплейса: как платформа переводит деньги исполнителям —
   поддерживает ли банк split-платежи / субмерчантов / выплату по расписанию,
   и какая отчётность по каждой транзакции.
4. Комиссия: процент за интернет-эквайринг, комиссия за возврат (refund),
   плата за подключение и абонентская плата, если есть.
5. Сроки: сколько дней занимает договор и техническое подключение, выдаёт ли
   банк **тестовые (sandbox) реквизиты до подписания договора**.
6. Технические требования: интеграция по API/redirect, документация, webhook
   для подтверждения платежа, требования к описанию сайта.
7. Реквизиты для ответа: e-mail и телефон.

## Как сравнивать ответы (заполнить после каждого ответа)

| Банк   | Комиссия % | Split/выплаты | Sandbox до договора | Webhook | Срок подключения |
| ------ | ---------- | ------------- | ------------------- | ------- | ---------------- |
| Arca   |            |               |                     |         |                  |
| Ameria |            |               |                     |         |                  |
| Idram  |            |               |                     |         |                  |
| Paynet |            |               |                     |         |                  |

Решение принимается не по самой низкой комиссии, а по сумме: split для
маркетплейса экономит часы ручных расчётов, sandbox до договора позволяет
начать 5.1–5.3 до подписания, а webhook обязателен — подтверждение брони
сверяется с банком (`getPayment()`), а не приходит «на слово».

## Что прислать разработчику после выбора банка

1. Название провайдера и выделенный тестовый (sandbox) мерчант.
2. Пары значений для `.env` (ровно эти имена уже поддержаны в коде):
   - Paynet: `PAYNET_API_URL`, `PAYNET_MERCHANT_ID`, `PAYNET_API_KEY`,
     `PAYNET_WEBHOOK_SECRET`;
   - Arca EPG: `ARCA_EPG_API_URL`, `ARCA_EPG_USERNAME`, `ARCA_EPG_PASSWORD`;
   - Ameria VPOS: `AMERIA_VPOS_API_URL`, `AMERIA_VPOS_CLIENT_ID`,
     `AMERIA_VPOS_USERNAME`, `AMERIA_VPOS_PASSWORD`;
   - Idram: `IDRAM_MERCHANT_ID`, `IDRAM_SECRET_KEY`;
   - и в любом случае `PAYMENT_PROVIDER=<имя>` в прод-окружении.
3. PDF документации по API — от неё зависит оценка задач 5.1–5.3.

До получения реквизитов включать прод-провайдер нельзя: при неполных
переменных приложение честно падает на старте с перечнем недостающего — это
сделано намеренно, чтобы платёж не сломался на клиенте.
