# Вычитка переводов носителем (задача 8.1)

На сайте три языка: армянский (основной), русский, английский. Русская и
английская версии написаны разработчиком и проверены автоматикой парности
ключей (`npm run i18n:check` — 1253 ключа × 3 локали). Но никакая автоматика
не проверяет **качество** армянского текста: на основном языке сайта
грамматическая ошибка видна первой и убивает доверие сильнее битой ссылки.

Вычитку делает носитель армянского с опытом копирайтинга. Это 1–2 дня работы
и делается один раз; второй раз понадобится после правового пакета (шаг 0.8),
когда юрист обновит тексты `/legal/*`.

---

## Что показывать вычитчику

Показывать **сайт**, а не файлы. Файлы (`src/i18n/messages/hy.ts`) — для
внесения правок, но человек должен видеть тексты в контексте: кнопки,
заголовки, пустые состояния, письма об ошибках.

Как запустить локально (нужен Node 22+, база не требуется для чтения):

```bash
npm install
npm run db:seed      # демо-данные
npm run dev
# открыть http://localhost:3000/hy
```

Для правок достаточно: файл `src/i18n/messages/hy.ts`, правки вносятся в
строки, для проверки — `npm run i18n:check`.

## Обход сайта по приоритету

| Приоритет | Где                                                | Что проверять                                                           |
| --------- | -------------------------------------------------- | ----------------------------------------------------------------------- |
| 1         | Главная, шапка, футер                              | первое впечатление; слоган и названия секций                            |
| 2         | Каталог: направления, занятия, инструкторы, студии | названия жанров, единицы («занятие», «проведение», «место»)             |
| 3         | Формы: регистрация, вход, бронирование, корзина    | подписи полей, сообщения об ошибках — они пишутся на языке пользователя |
| 4         | Кабинет, страницы оплаты                           | кнопки действий, суммы, статусы                                         |
| 5         | Письма (шаблоны в `src/lib/email/`)                | тема и приветствие письма                                               |
| 6         | Правовые страницы                                  | только после юриста                                                     |

Вести правки в таблице «где → было → стало → комментарий» — так разработчик
внесёт всё за один проход и ничего не потеряет.

## Типовые ловушки (проверить отдельно)

1. **Заимствования.** «бронирование», «оплата», «отмена» — выбрать один
   вариант перевода и держать его по всему сайту. Сейчас в hy-файлах
   встречаются и Armenian-, и русско-калькированные варианты; носитель
   должен унифицировать.
2. **Формы чисел.** Армянский плюрал отличается от английского; ICU-плюралы
   уже расставлены, но носитель проверяет живые фразы вида «3 места
   свободны».
3. **Вежливость кнопок.** «Отправить»/«Отправляй» — тон кнопок должен быть
   единым.
4. **Названия жанров.** Возможно, часть жанров уместнее оставить латиницей
   (Salsa, Bachata) — так делают локальные площадки; решение фиксируется.
5. **Валюта.** Формат «5 000 ֏» уже выбран; проверить чтение вслух в
   контексте («пять тысяч драмов», а не «пять ноль ноль»).

## После вычитки

1. Правки вносятся в `hy.ts` (и в параллельные ключи ru/en, если правка
   меняет смысл, а не только язык).
2. `npm run i18n:check` и `npm run test` — зелёные.
3. В `docs/03-conventions.md` §9 вопрос «Вычитка армянских переводов
   носителем» помечается решённым, с датой и именем вычитчика.
4. Повторный проход — только по изменённым разделам (git diff покажет).
