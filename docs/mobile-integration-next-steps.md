# Интеграция мобильного приложения: что дальше

Дата обновления: 2026-10-26.

## Состояние

### Веб (Next.js)
- Кабинет `/studio`: доступность, check-in и занятия инструктора. Заглушка `Requests` удалена: отдельного источника заявок в текущем продукте нет.
- Кабинет `/venue`: список площадок, залы, предстоящие бронирования и назначение зала на занятие через общую мутацию `assignClassSessionRoom`.
- Обычные события бронируются через общий `Booking`; соревнования сохраняют отдельную форму регистрации с категориями.
- Подарочная карта `gift-card` продаётся как обычный товар через страницу товара, корзину и checkout.
- Выключенные возможности показывают нейтральное `Unavailable`/`Недоступно`/`Հասանելի չէ`, а не обещание будущего запуска.

### Мобильное приложение (Expo)
- Экран доступности студии есть: `mobile/app/studio/availability`.
- Добавлены занятия инструктора: `mobile/app/studio/classes.tsx`.
- Добавлен кабинет площадки: список залов, ближайшие брони и занятия в `mobile/app/venue/index.tsx`.
- Добавлен отдельный экран выбора зала: `mobile/app/venue/room-assignment.tsx`.
- Нативная аренда студии работает через `mobile/app/studio/[slug]/book.tsx`, `/api/catalog/studios/[slug]/rent`, `/api/booking/hold` и `/api/booking`.
- Обычные события используют `/api/events/[slug]/book`, затем общий booking/payment flow; `/api/events/[slug]/register` остаётся для соревнований.
- Подарочные карты открывают native product/cart/checkout flow, без web-заглушки.
- Пакеты занятий можно купить из native pricing screen через `/api/class-passes/purchase` и общий payment flow.
- Account, help, legal, contact, password reset, checkout и partner dashboards открываются нативно. В браузер отправляются только лендинги из явного allowlist.
- Переменные окружения мобильного приложения (`mobile/.env`, `mobile/.env.local`, читаются при старте Metro, после изменения нужен `npx expo start --clear`):
  - `EXPO_PUBLIC_API_URL` — адрес веб-сервера. Для разработки в локальной сети укажите `http://<IP машины>:3000` (сервер отдаёт только HTTP).
  - `EXPO_PUBLIC_TURNSTILE_SITE_KEY` — тот же ключ, что `NEXT_PUBLIC_TURNSTILE_SITE_KEY` на сервере. Если на сервере включён Turnstile, приложение показывает native WebView-челлендж (`mobile/src/components/ui/turnstile-challenge.tsx`) и отправляет проверенный токен; клиентский флаг не отключает серверную проверку.

## Что реализовано 2026-10-26

- Проведён аудит источников данных: веб и мобильное приложение используют общие server-query и доменную мутацию.
- Добавлены API для мобильного кабинета:
  - `GET /api/studio/classes`;
  - `GET /api/venue`;
  - `GET/POST /api/venue/room-assignment`.
- Добавлены API для нативных рабочих сценариев:
  - `POST /api/events/[slug]/book`;
  - `GET /api/catalog/studios/[slug]/rent`;
  - `POST /api/class-passes/purchase`;
  - native contact/password-reset используют реальные серверные endpoints и Turnstile.
- API используют Bearer-сессию, entitlement `events`, проверки владельца/членства и те же проверки конфликтов залов, что и веб.
- Карточка «Заявки» удалена из мобильного кабинета: в текущем веб-коде нет раздела или источника данных Requests, поэтому отдельный выдуманный API не добавлялся.
- Добавлены переводы новых экранов для `en`, `ru`, `hy`.

## Проверка перед коммитом и пушем

- Корневая проверка: `npm run verify`, затем `npm run build`.
- Мобильная проверка: `cd mobile && npm run typecheck && npm test`, затем Expo web export.
- Локальный e2e требует включённую службу Postgres `postgresql-x64-17`; для запуска нужен админ-доступ: `Set-Service -Name postgresql-x64-17 -StartupType Manual` и `Start-Service -Name postgresql-x64-17`.
- Миграции и сид запускать только на localhost (явно задать `DATABASE_URL` и `DIRECT_DATABASE_URL`). Не запускать против Supabase.
- Пушить только после проверки рабочей копии, зелёных локальных проверок и подтверждения пользователя; после пуша дождаться нового CI именно для текущего commit.
- Армянские строки (`hy`) нужна проверка носителем языка.
